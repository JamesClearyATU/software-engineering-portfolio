## Task 1
 | Area | Waterfall | Agile |
 |---|---|---|
 | Requirements | The requirements would need to be updated because the new feature wasnt included originally | The new feature would be added to the backlog and planned into future sprints |
 | Design | The team would have to go back and change parts of the design that were already finished | The design could be updated as the team works on the new feature |
 | Approvals | The client and project manager would need to approve the updated requirements and design before work continues | The client could review the changes and give feedback during each sprint |
| Development | The team would need to redo parts of the ordering system, payment splitting, kitchen notifications and some screens | The new feature could be split into smaller tasks and worked on over a few sprints |
| Testing | The test plans would need to be updated and the team would need to test the changed parts and that the old features still work | Testing could be done during each sprint | 
| Time | The project could end up taking longer and costing more because of it | It would be easier to fit the change into the project but it would still take extra work to do |
| Cost | It would cost more because of the extra development, approvals and testing | It would usually be easier to manage, but the extra work would still cost time and money. |

I think agile would be better for this situation because it gives the team more flexibility when the client wants something changed and with waterfall the team would have to go back and redo work that was already approved and done. With agile they could plan changes into future sprints instead. It would be extra work either way but agile would be easier to manage.
